## 2. 실행자에게 제공할 입력

<b>요청문</b>

“제공된 회원 인증을 사용해 게시판 웹 기능을 만들어라. 누구나 게시글 목록과 상세를 읽을 수 있고, 로그인한 회원은 제목과 본문을 가진 글을 작성할 수 있어야 한다. 수정·삭제는 작성자만 가능하며 서버에서도 권한을 검사해야 한다. 정상 저장 결과가 새로고침과 앱 재기동 후 유지되고, 거절한 요청이 데이터를 바꾸지 않았음을 확인할 수 있게 실행·검사·초기화 방법을 제공하라. 댓글·검색·파일 첨부는 구현 범위에서 제외한다.”

<b>공개 요구사항</b>

- BOARD-R1: 비회원 포함 누구나 목록·상세를 읽는다. 빈 목록은 오류 없이 빈 상태로 표시한다. 최소 아래 3개 글을 모두 찾아 열 수 있어야 한다. 정렬·페이지 크기는 자유지만 README에 공개하고 반복 비교에서 고정한다.
- BOARD-R2: 로그인 회원은 제목·본문이 있는 글을 생성한다. 작성자는 서버가 인증 주체에서 결정하며 입력의 작성자 ID로 다른 사람을 사칭할 수 없다.
- BOARD-R3: 작성자만 본인 글의 제목·본문을 수정하거나 삭제한다. 수정은 글 ID·작성자를 유지한다. 삭제된 글은 목록에서 사라지고 기존 주소로 읽을 수 없다. 내부 soft/hard delete는 자유다.
- BOARD-R4: 비회원의 쓰기와 다른 회원의 수정·삭제는 직접 서버 요청에서도 거절한다. 거절 후 모든 대상 데이터는 이전 상태를 유지한다.
- BOARD-R5: 제목·본문 각각 누락·빈 문자열·공백만 있는 값은 UI와 서버에서 거절한다. 잘못된 수정으로 기존 내용이 없어지면 안 된다. 길이 상한은 아래 정상 입력을 허용하면 구현 선택이며 이번 버전에서는 점수화하지 않는다.
- BOARD-R6: 존재하지 않거나 삭제된 글은 없는 자료로 처리하고 글을 새로 만들거나 다른 글을 변경하지 않는다.
- BOARD-R7: 저장 성공한 내용은 새로고침·다른 컨텍스트 조회·앱 재기동 후에도 일치한다. 본문은 일반 텍스트이며 줄바꿈과 한글을 보존한다. 문자열을 실행 가능한 HTML로 해석하지 않는다.
- 공개 읽기와 작성자 권한은 예제 벤치마크의 설계값이다. 실제 서비스의 정책을 대신 확정하지 않는다.

<b>입력 자료 — BOARD-DATA-v1</b>

| 별칭 | 작성자 | 제목 | 본문 |
| --- | --- | --- | --- |
| P1 | A | 첫 번째 글 | 안녕하세요. + 줄바꿈 + 게시판 테스트입니다. |
| P2 | B | 두 번째 글 | 다른 회원의 글입니다. |
| P3 | A | 세 번째 글 | 새로고침 후에도 남아야 합니다. |
| P1-edit | A | 수정한 첫 번째 글 | 수정된 본문입니다. |
| 오류 입력 | A | 빈 값·공백 3개·필드 누락을 각각 사용 | 빈 값·공백 3개·필드 누락을 각각 사용 |

P1 본문의 “+ 줄바꿈 +”는 실제 개행 문자 1개로 입력한다. 잘못된 제목을 시험할 때 본문은 P1 정상값, 잘못된 본문을 시험할 때 제목은 P1 정상값을 사용한다. 텍스트 해석 검사에서는 별도 글의 본문으로 아래 문자열을 그대로 입력한다.

```txt
<strong>문자 그대로</strong>
```

합성 데이터 표와 코드 블록이 원본이다. 별도 seed 파일·검사 스크립트는 아직 없다. 시작 상태는 회원 A/B가 존재하고 서로 격리된 인증 컨텍스트를 공급받으며 게시글은 0건이다. 구현·수정은 지정된 시험 앱과 데이터에 한정한다.

- 출력: 생성된 글 ID와 작성자 ID 대응표, 목록·상세 조회 수단, 저장 상태 관찰 수단.
- 회원 ID와 글 ID의 타입이 서로 같을 필요는 없다. 인증 공급자의 회원 ID와 글의 작성자 ID는 타입·의미가 일치해야 한다. 타입 변환이 필요하면 손실 없는 명시적 매핑과 검사를 문서화한다.
- REST·GraphQL·서버 액션 등 전송 형태와 경로, 저장소와 UI는 자유다. 화면 조작만으로 권한을 검사했다고 보지 않으며 실제 서버 진입점으로 재요청한다.
- 독립 시험의 인증 fixture는 구현이 실제로 존재하고 동일한 신뢰 경계를 재현해야 한다. 클라이언트가 임의 ID를 넣으면 인증되는 흉내만으로 통합 성공을 주장하지 않는다.

판정은 통과 / 실패 / 미실행 / 판정불가. 인증 공급 실패로 BOARD-07을 시작하지 못하면 미실행으로 남기며 인증 실패와 게시판 권한 결함을 구분한다. 실패를 평균 점수로 상쇄하지 않는다. 측정 수식·분모와 개발 과정 평가는 metrics DB 및 대상별 평가 명세에 둔다. 현재 선택된 지표·평가 명세 없음.

실제 명령은 구현 후 README에 고정하고 시험용 데이터임을 확인한 상태에서 수행한다. BOARD-10 재기동 중에는 DB 데이터를 지우지 않는다. 각 시나리오 초기화와 지속성 시험의 재기동은 목적이 다르다.

증거 계약: trial·시나리오 ID, commit, 시각, 사용자 별칭/실제 ID 매핑, 입력, 마스킹한 서버 응답, UI, 저장 상태 전후, 판정·이유. 권한 거절은 오류 응답만 보지 않고 저장 불변을 확인한다. 실제 결과는 할 일 PART 2에 기록한다. 자동 검사·참고 구현·비공개 정답 데이터는 아직 없다.
