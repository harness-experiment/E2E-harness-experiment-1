# 테스트1 실행 계약

모델은 사용자 지정 Astra-6-medium, 호스트 제공 식별자는 gpt-6-astra다. 추론 설정의 별도 관측값은 제공되지 않았다. 단일 개발 trial이며 기준 커밋은 dd0a408097793afc7d9f2f7d4b5d46ab8667a09b다. 기존 제품 코드·DB를 가져오지 않았다. 시험용 DB는 board_trial1이며 앱 포트 18081, UI 15173, PostgreSQL 15433을 사용한다.

사용자는 구현·로컬 검증·추가 유료 자원 0원·환경 오류 재시도 최대 2회를 승인했다. 6시간 중간 판정 조건은 삭제했다. PR 게시 승인은 검증 자료 제출 후 받고, Vercel·Railway 배포는 사용자가 수행한다.

## 구현과 검사 계약

Java 21, Spring Boot 4.1.2, Gradle 9.2.1, React, PostgreSQL 16을 사용한다. 회원 ID와 글 ID는 서버 생성 BIGINT다. 이메일은 입력 문자열 그대로 유일성을 검사한다. 비밀번호는 BCrypt 해시, 인증은 30분 서버 세션이다. 세션 재기동 유지 자체는 요구하지 않는다. CSRF 토큰을 모든 변경 요청에 요구하고 UI와 API는 동일 출처 프록시로 연결한다.

회원 가입·로그인·로그아웃·현재 사용자 경로는 /api/auth 아래 signup, login, logout, me다. 가입 201, 중복 409, 잘못된 입력 400, 인증 필요 401, 권한 부족 403, 없는 글 404로 응답한다. 실패 응답은 message 필드다. 게시글은 /api/posts 및 /api/posts/{id}에서 GET/POST/PUT/DELETE를 제공한다. 제목 200자, 본문 10000자, 비어 있거나 공백뿐인 입력은 거절한다. 작성자 값은 서버 인증 주체에서 정한다. 목록은 ID 내림차순으로 전부 반환한다. 수정은 마지막으로 성공한 요청을 반영하고 SQL 변경은 원자적으로 처리한다.

화면은 공개 목록·상세·가입·로그인·작성·수정이다. 각 화면은 로딩·빈 상태·오류를 표시한다. 쓰기 버튼은 처리 중 비활성화한다. 글 본문은 React 텍스트 노드와 pre-wrap으로 한글·개행·태그 문자열을 보존한다.

## 검증과 품질 기준

AUTH 8개, BOARD 11개, INT 5개의 하위 입력을 API·UI·저장 상태로 대조한다. 단위 테스트는 입력·권한·인증 실패, 통합 테스트는 DB·HTTP·세션, E2E는 실제 브라우저 흐름을 검증한다. 소스·테스트·스크립트 모두 품질 평가 대상이다. 13개 코드 품질 기준을 적용하며 독립 사람 검토가 필요한 HFM-05는 모델 보조 평가로 표기한다.

변경 시나리오는 제목 길이 변경, 인증 만료 변경, 목록 페이지네이션, 저장소 연결 변경이다. 정책 변경 위치를 찾을 수 있고 UI·서버 검증이 충돌하지 않아야 한다. API·서비스·저장소 책임을 분리하고 사용하지 않는 확장 계층을 만들지 않는다. Java는 Spotless, 프론트·스크립트는 Prettier·ESLint로 검사한다.

## 승인된 운영 시험

기본 기능 검증 직후 k6 5 VU, 60초, 1회. 오류율 1% 미만과 p95 500ms 미만이 수용 기준이다. 오류율 5% 또는 p95 2초 초과가 10초 지속되면 중단한다. 시험 데이터와 루프백 주소에 한정한다. 장애는 시험 앱 1회 중단·재기동이며 탐지 30초, 복구 60초 안에 데이터 유지·기능 회복을 확인한다. 장애 시험의 예상 실패 응답은 정상 부하 시험과 별도 증거에 남긴다.

## 측정 한계

HFM-01~12 정의를 읽고 해당 지표에 관측값 또는 미측정 사유를 남긴다. 신규 개발이므로 HFM-04 회귀 기준은 해당 없음, 독립 반복이 1회이므로 HFM-06 반복 신뢰성은 해당 없음, 대응 기준 trial이 없어 HFM-12 비교 효과는 해당 없음이다. 모델 과금 정보가 제공되지 않으면 HFM-10·11을 추정하지 않는다. 최초 사용자 요청 시각은 수집되지 않아 HFM-09 전체 경과시간을 개발 시작 시각으로 대체하지 않는다.
